# Доска агентов

Одна доска на все проекты: записываете задачу, выбираете модель и уровень усилий, отправляете в облако Claude. Результат возвращается на доску: ссылка на страницу, скриншоты, отчёт агента, проверки. Дальше «Принять», «Доработать» или «Отклонить».

## Запуск

```
cd ~/Developer/laboratory/agent-board
npm start        # собирает интерфейс и запускает доску: http://localhost:5194
npm run check    # типы и все тесты
```

## Как работать

1. Сверху напишите задачу своими словами. Первая строка станет заголовком.
2. Выберите модель и усилие. **Сохранить в идеи** ничего не запускает и ничего не стоит, **Отправить в облако** запускает сессию (`⌘↵`). После этого ноутбук можно закрыть.
3. Когда задача в колонке «На проверке», откройте карточку: превью сайта, скриншоты, отчёт, проверки.
4. **Принять** вливает результат в staging, **Доработать** отправляет правку в ту же сессию, **Отклонить** закрывает PR и удаляет ветку.

Клавиши: `N` новая задача, `J` и `K` соседние карточки, `Esc` закрыть панель, `?` подсказка.

## Облачный профиль проектов

У каждого проекта в `config.json` есть профиль: можно ли отдавать его задачи в облако, что именно можно и нельзя. Для проектов только с локальной разработкой кнопка облака скрыта, а API откажет. Режим «без проверки при зелёных тестах» включается для отдельной задачи и только там, где проект его разрешает.

## Разовая настройка

1. `gh auth login` и `claude auth login`.
2. Claude GitHub App на репозитории проекта: https://github.com/apps/claude. Без него облако получит архив, а не клон.
3. Первая отправка создаёт клон `data/dispatch/<проект>`. Откройте его в терминале (`cd data/dispatch/<проект> && claude`) и ответьте «Yes, I trust this folder»: это спрашивается один раз.
4. Адреса своих серверов кладите в `config.local.json` (в git не попадает):

```json
{ "projects": { "coffee-site": { "stagingUrl": "http://…:8080/", "prodUrl": "http://…/" } } }
```

## Ограничения

- Полный лог облачной сессии доступен только на claude.ai (ссылка есть в карточке): программного доступа нет.
- Облако не умеет iOS и всё, что требует macOS, и не достаёт до ваших локальных файлов и сервисов.

## Страница «Облако» на сервере

Тот же интерфейс в режиме просмотра публикуется на сервер проекта (порт 8090, под паролем): там видно, что сейчас делает облако и как прошла работа, а Mac может быть выключен. Данные берутся из PR репозитория, поэтому задачи, ещё не дошедшие до GitHub, там не видны. Подключение проекта: workflow `Status` из шаблона `harness/templates/cloud-repo`.
