# agent-board

Локальная доска задач для облачных агентов Claude. Работает на Маке (`npm start`, порт 5194, только 127.0.0.1). Задачи хранятся в `data/tasks.json` (в git не попадает). В облако уходит текст задачи в промпте `claude --cloud`; ход работы и результат доска читает с GitHub через `gh`, токены в браузере не нужны. Node 22 и новее, зависимостей нет.

## Устройство

```
server/
  index.mjs       запуск, планировщик синхронизации (цепочка таймеров: циклы не накладываются)
  config.mjs      config.json + config.local.json, проверка, облачный профиль проекта
  derive.mjs      чистые функции: статус из PR, поиск PR по заголовку, разбор комментария превью, решение авторежима
  store.mjs       хранилище задач, атомарная запись, приведение старых задач к текущей форме
  tasks.mjs       сервис: жизненный цикл, замок на задачу, фоновые операции, синхронизация
  github.mjs      gh: PR, комментарии, проверки, слияние
  claude.mjs      облачные сессии: запуск через pty-dispatch.py, правка в ту же сессию
  workspace.mjs   отдельный клон проекта для запуска сессий (рабочую папку не трогаем)
  http.mjs        маршруты, защита, статика
web/              интерфейс на ES-модулях без сборки (state, board, pane, composer, settings, main)
test/             node --test: derive, store, tasks, http (npm test)
```

## Модель состояний

`backlog` → `running` → `review` → `done`, а также `failed` и `closed`. Состояние выводится из PR задачи (`derive.mjs`): draft и «Ход работы» значит идёт работа; «## Отчёт» без draft значит готово к проверке; «СБОЙ:» значит сбой; влитый PR значит принято. PR находится по заголовку `[#N] …`, имя ветки облако назначает само. После доработки отчёт считается новым, только когда тело PR изменилось. Правка идёт в ту же сессию: `claude -p … --cloud <session_id>`.

## Облачный профиль проекта

`config.json` → `projects[].cloud`: `mode` (`full`, `partial`, `local`), `summary`, `can`, `cannot`, `autoAllowed`. Доска не даёт отправить в облако задачу проекта с режимом `local` ни из интерфейса, ни по API. `autoAllowed` разрешает для задачи режим «без проверки»: при зелёных тестах в облаке результат вливается в staging сам. Личное (адреса серверов, `stagingUrl`, `prodUrl`) лежит в `config.local.json`, он в git не попадает.

## Правила

- Логика состояний только в `derive.mjs` и `tasks.mjs`, без ввода-вывода в `derive.mjs`; всё новое поведение закрывается тестом.
- Долгие операции (запуск сессии, доставка правки) идут в фоне: ответ приходит сразу, итог пишется в задачу.
- Любой ввод и всё, пришедшее из GitHub, попадает в DOM через `textContent` или `md()`, которая экранирует ввод.
- Изменяющие запросы принимаются только с JSON и с Host `localhost` или `127.0.0.1`.
- Запуск `claude --cloud` идёт из отдельного клона `data/dispatch/<проект>`: его нужно один раз открыть в `claude` и подтвердить доверие, иначе доска вернёт понятную ошибку.

## Открыто

- Полный лог облачной сессии программно не отдаётся: доска показывает ход из PR, коммиты, проверки и ссылку на сессию.
- Локальный запуск задач (`claude --bg` в worktree) пока не сделан: задачи проектов с режимом `local` остаются в идеях.
- Зависшая сессия остаётся «в работе»: через 30 минут без PR доска подсказывает открыть сессию.
