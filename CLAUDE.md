# agent-board

Доска облачных задач Claude. Один интерфейс в двух режимах: **управление** (локально на Маке: идеи, отправка в облако, принять, доработать, отклонить) и **просмотр** (страница «Облако» на сервере проекта: что сейчас делает облако, читается из GitHub, Мак может быть выключен). Режим определяется сам: если отвечает локальный сервер доски, страница управляет, иначе читает опубликованные снимки.

## Стек и команды

Интерфейс: React 19, TypeScript, Vite, Tailwind v4, shadcn (стиль `base-nova`, примитивы Base UI), Inter. Сервер: Node 22+, без зависимостей. Версии согласованы с `laboratory/crm-kit-v3`.

- `npm start` собрать интерфейс и запустить сервер (http://localhost:5194).
- `npm run dev` Vite на порту 5195 с проксированием `/api` на запущенный сервер.
- `npm run check` типы, тесты сервера (`node --test`) и интерфейса (`vitest`).
- Компоненты shadcn добавляются штатно: `npx shadcn@latest add <имя>`, лежат в `web/src/components/ui`.

## Устройство

```
server/   index, config, derive (чистая логика состояний), store, tasks (сервис), github, claude, workspace,
          snapshot (снимок облачных задач из PR), http
web/src/  main, app; hooks/ (board: данные, выбор, действия), lib/ (source: режимы, api, markdown, status, prefs, format),
          components/ (board, pane, composer, app-header, диалоги), components/ui (shadcn на Base UI)
test/     тесты сервера;  web/src/**/*.test.*  тесты интерфейса
```

Публикация для страниц на серверах: workflow `ui.yml` собирает `dist` и кладёт в ветку `ui`; workflow `Status` в проектах берёт её, строит снимок командой `node server/snapshot.mjs` и кладёт на сервер.

## Модель состояний

`backlog` → `running` → `review` → `done` (или `failed`, `closed`). Состояние выводится из PR задачи (`server/derive.mjs`): draft и «Ход работы» значит идёт работа; «## Отчёт» без draft значит готово к проверке; «СБОЙ:» значит сбой; влитый PR значит принято. PR находится по заголовку `[#N] …`. После доработки отчёт считается новым, только когда тело PR изменилось. Правка идёт в ту же сессию (`claude -p … --cloud <id>`).

## Облачный профиль проекта

`config.json` → `projects[].cloud`: `mode` (`full`, `partial`, `local`), `summary`, `can`, `cannot`, `autoAllowed`. Для `local` доска не даёт отправить задачу в облако ни из интерфейса, ни по API. `autoAllowed` разрешает режим «без проверки при зелёных тестах». Личное (адреса серверов) в `config.local.json`, он не попадает в git.

## Правила

- Логика состояний только в `derive.mjs` и `tasks.mjs`, без ввода-вывода в `derive.mjs`; всё новое закрывается тестом.
- Данные и ввод попадают в интерфейс только как текст (компонент `Markdown` строит элементы, без `dangerouslySetInnerHTML`).
- Цвет означает только состояние задачи (токены `--state-*`); остальное нейтральное. Свои стили только через токены темы и классы Tailwind.
- Изменяющие запросы принимаются только с JSON и Host `localhost`/`127.0.0.1`.
- Запуск `claude --cloud` идёт из отдельного клона `data/dispatch/<проект>` (папку нужно один раз подтвердить как доверенную).

## Открыто

- Полный лог облачной сессии программно не отдаётся: доска показывает ход из PR, коммиты, проверки и ссылку на сессию.
- Локальный запуск задач (`claude --bg` в worktree) пока не сделан.
